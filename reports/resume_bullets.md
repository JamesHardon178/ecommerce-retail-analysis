## 版本 A · 完整 STAR 版（推荐，适合项目经历主位）

**电商销售增长与客户复购分析平台**（个人项目 | Python / SQL / Streamlit）

- **S/T**：零售企业普遍面临三类分析困境——原始交易数据脏乱重复导致指标不可信、报表只报数不给结论、异常波动无法定位原因。基于 106.7 万行真实零售交易流水（UCI Online Retail II，25 个月），独立完成从数据治理到业务决策的端到端分析。
- **A（数据治理）**：设计 7 段互斥分段清洗规则（识别双 sheet 时间重叠的 34,335 行重复、1.9 万行取消单、22.8 万行匿名交易），以**行数守恒断言**保证每行数据去向可追溯、口径加总 100% 闭环；构建 SQLite 分析库与 9 条窗口函数专题 SQL（LAG/RANK/NTILE/ROW_NUMBER），并建立 **SQL 与 Pandas 双路径交叉验证（16 项指标一致）+ 9 个 pytest 口径测试**的三层质量防线。
- **A（业务归因）**：用三因素分解定位异常月根因——3 个收入异常月全部由订单量效应驱动而非客单价下滑；通过客户级诊断发现 EIRE 市场暴跌 24.3% 的真实原因是**单一头部客户砍单 -37%**（非市场性萎缩）；识别出收入榜第 4 的商品收入与退款完全对冲（£168,470）的"虚假热销"现象。
- **R（业务结论与策略）**：量化复购率 **72.4%**、前 10% 客户贡献 **63.9%** 收入、Cohort M+1 留存 **20.3%**（旺季拉新留存反而更差，低至 9.2%）、退货率 **7.1%**（单笔异常占退款 11.5%）等核心指标，输出**大额订单预审批、新客首单复购券、前 10% 客户 VIP 运营防线、市场×客户双维集中度预警** 4 项可落地的业务策略；交付 Streamlit 5 页看板，所有图表标注时间范围与统计口径，并显式标记数据截断月避免管理层误读。

## 版本 B · 精简版（1 条，适合空间紧张）

**电商销售增长与客户复购分析平台**（Python / SQL / Streamlit）— 针对"指标不可信、报表无结论、异常难定位"三大痛点，基于 106.7 万行真实零售流水构建端到端分析框架：7 段互斥清洗实现行数守恒 100% 闭环，9 条窗口函数 SQL 与 Pandas 交叉验证 16 项一致；定位异常月根因（订单量效应主导）、识别虚假热销商品与单笔 £168K 退款黑天鹅、诊断出 EIRE 市场暴跌实为单一客户砍单，输出大额订单预审批、新客复购券、VIP 运营防线等 4 项业务策略；核心指标复购率 72.4%、前 10% 客户贡献 63.9%、M+1 留存 20.3%。

## 版本 C · 突出 SQL 工程与数据质量（适合强调技术深度）

- 编写 **9 条 SQLite 窗口函数查询**（CTE + LAG 环比/同比 + RANK + NTILE + 累计 SUM OVER），覆盖月度趋势三因素分解、RFM 八分层、Cohort 留存矩阵、客户帕累托、HHI 商品集中度；设计"同口径年度窗口"对比修正数据截断（2011-12 仅 8 天）导致的同比失真——避免把数据缺陷误读为业务崩盘。
- 建立**三层可审计质量防线**：清洗层行数守恒断言（分段加总 == 原始 1,067,371 行）→ 分析层 SQL vs Pandas 16 项指标对账 → 测试层 9 个 pytest 口径不变式（退货表零重叠、判重 8 列口径、截断月识别）；在交叉验证中实际发现并修正过一次"全期占比 vs 窗口占比"的口径不一致缺陷，验证了该防线的有效性。

## 面试追问弹药库（背下来，每条都基于真实数据）

| 可能的问题 | 真实答案 |
|---|---|
| 净收入怎么算？ | 销售收入 £20,476,260（数量>0 且单价>0）− 退货 £1,462,424 = 净收入 £19,013,836；客单价 £474.43（净收入/40,077 单） |
| 复购率 72% 是不是太高？ | 这是 B2B 批发数据，客户本身高频下单；因此我同时用"前 10% 客户贡献 63.9% 收入"来刻画客户结构，单看复购率会高估忠诚度 |
| 数据质量最大的坑？ | ① 双 sheet 在 2010-12 时间重叠，产生 34,335 行完全重复；② 2011-12 数据止于 12-09 仅 8 天，直接同比会得出"-70% 崩盘"的错误结论；③ Invoice 列混合类型（int + 'Cxxx'），不统一成字符串会让取消单识别静默失效 |
| 异常月怎么归因？ | 把 Δ净收入 分解为订单量效应 + 客单价效应 + 退款效应（LAG 取上期值），3 个异常月全部是订单量主导——策略结论是"抓拉新和唤醒，不是调价" |
| 退货分析最重要的发现？ | 退货率 7.14% 看着正常，但单笔 £168,470 就占 11.5%；剔除后主要是 AMAZONFEE 等费用冲销——问题不在货，在少数大额订单的履约/结算，所以策略是大单预审批而非全面质检 |
| EIRE 暴跌 24.3% 怎么归因？ | 下钻到客户级：全市场只有 5 个有 ID 客户，2 个大客户占 91.6% 收入；暴跌主因是客户 14156 砍单 -37%（£185K→£117K），另一大客户稳定——是"一个大客户减单"，不是市场萎缩，策略是大客户面谈而非渠道投放 |
| 如果继续做会做什么？ | ① 单笔 >£50K 大额订单履约预警 ② "国家收入 TOP1 客户占比>50%"双维集中度监控（EIRE 是首个触发样本）③ 首购后 30 天未复购的自动唤醒策略并做 A/B 验证 |
